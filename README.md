### 🧬 RME (2000 → 2001) — метаморфный рекомпилятор x86-кода (TASM, DOS)
- **Ядро для защиты кода**: полная перекомпиляция тела с сохранением семантики — та же база, что в ASProtect, VMProtect, Themida
- **Компиляторный конвейер**: disasm → IR (DNA → mRNA) → трансформация → ref_fixup → эмиссия → верификация
- **Таблицы диспетчеризации**: расширяемые дизассемблер и мутатор — новые типы инструкций и HLL-шаблоны добавляются без переписывания ядра
- **Мимикрия под компилятор**: маскировка под вывод Borland C++ 3.1 — приём, который позже стал стандартом в обфускаторах (OLLVM, Tigress)
- **Устранение Get-IP**: IP-относительные ссылки → абсолютные. Экономит 1 байт на инструкцию
- Автоматический пересчёт всех ссылок после изменения длин инструкций — основа любого бинарного переписчика (r2morph, QEMU TCG)
- Режимы: полиморфный, метаморфный, полный — гибкость под задачу
- **Отладка и валидация**: DNA/mRNA дампы, PASS/FAIL проверки — инструментальный уровень, редкий для 2001 года
- **Концептуально портируем на 32/64 бита**: конвейер, IR и диспетчеризация — универсальный шаблон для бинарных трансформеров
→ [github.com/andrei-ag/rme](https://github.com/andrei-ag/rme)

### 🎯 **СУПРА** — Система Управления Приоритетами РАбот (2025 → now) **[личный проект]**

Расширение для конфигураций на базе [1С:БСП](https://v8.1c.ru/tekhnologii/standartnye-biblioteki/1s-biblioteka-standartnykh-podsistem/). Режим совместимости: Версия 8.3.26

Открытая система управления проектами, вдохновленная:
- **Jira/Agile** — гибкая методология, бэклог, спринты, полностью настраиваемая доска задач.
- **Приоритет = позиция в списке** — подход, реализуемый в MS Project через настройку "Leveling order = ID ONLY" (приоритет задачи определяется её порядковым номером в списке, а не абстрактным числом). → [gaperton.livejournal.com](https://gaperton.livejournal.com/19205.html)

Особенности:
- **Режим реального времени** — инкрементальный пересчёт **дат старта и окончания задач** по графу зависимостей. Асинхронно, без дополнительного нажатия кнопок и без блокировок интерфейса и карточек задач. Исполнители при этом **работают как обычно**: меняют статусы, трудоёмкость, атрибуты, вносят отчеты о работах — всё доступно.
- **Два режима загрузки ресурсов:** исполнитель может работать только над одной задачей в единицу времени (исключает параллельные назначения) — либо без этого ограничения.
